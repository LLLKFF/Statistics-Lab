# Statistics Lab Podcast Studio

> 把研究报告改写成真正适合听的市场播报，而不是把 Markdown 念一遍。

## 定位

Podcast Studio 是 Statistics Lab 的音频分发模块。它不独立生产市场结论，而是把同日已经完成并留有证据链的研究内容重新组织成可直接录制的播客脚本。

默认上游输入：

1. Global Macro Research Diary；
2. Market Radar；
3. 必要时引用同日重大事件研究、Prediction Ledger 与 Previous Call Review。

默认对外产品名：

**Statistics Lab Market Brief｜市场早报**

## 内容链路

```
Market Data / Public Sources
        ↓
Global Macro Research Diary
        ↓
Market Radar
        ↓
Podcast Studio
        ↓
Market Brief Script
        ↓
Audio / Podcast Platforms
```

Podcast Studio 只负责“怎么讲”，不改变“研究结论是什么”。

## 默认文风：财经特稿式播报

从 2026-09-24 起，Podcast Studio 默认采用“成熟财经特稿 + 可直接口播”的写法。

目标不是制造强烈的主播人格，也不是把研究报告改成闲聊，而是先写成一篇逻辑完整、信息密度高、自然可听的财经稿件，再让它适合被念出来。

### 核心特征

- **事实先行**：开头先落一个具体事实、反常现象或关键变化，再提出当天真正需要解释的问题。
- **单线推进**：每期围绕一条核心矛盾展开，用“现象 → 数据 → 解释 → 资产映射 → 后续验证”推进，不平铺多个平行主题。
- **数据嵌入叙事**：数字只在改变理解、确认趋势或构成关键阈值时出现，不朗读完整表格。
- **克制表达**：减少“我觉得”“说白了”“挺有意思”“市场还能忍”等个人化评论，让事实和机制本身推进判断。
- **自然口播**：句子可直接念，但不刻意追求短句、金句或段段反转。
- **结构化但不露结构**：底层仍遵守 Macro → Radar → Trading Map → Validation，但正文不频繁用“首先、其次、接下来”提醒听众。
- **结尾上收一层**：最后从当天行情回到更大的市场结构、产业逻辑或估值框架，同时保留明确的验证条件。

### 开场口径

每期保留一个稳定但不过度模板化的导引：

> 大家好，欢迎收听 Statistics Lab 的市场早报。
>
> 这里我们每天用十分钟左右，梳理前一个交易日最重要的市场变化。我们不追逐每一条新闻，更关心三个问题：市场究竟在交易什么，原来的逻辑有没有发生变化，以及接下来哪些信号最值得关注。

随后直接进入当天主题，不再额外增加主持人口号。

### 结尾品牌口径

固定使用：

> 完整数据、指标及相关分析，参见 Statistics Lab 的分析报告。

避免在口播里逐期朗读报告编号、文件名、参考文献或数据方法说明。

## 单期目标

- 时长：约 8–15 分钟；
- 中文正文：通常 2,000–3,500 字；
- 一期只保留一条核心叙事主线；
- 听众不看图表，也能理解市场当天在交易什么；
- 结尾必须给出次日最值得观察的 2–3 个验证条件；
- 交易相关内容必须以条件化研究表达，不写成喊单或确定性指令。

## 固定研究结构

### 1. Opening / Core Tension
用一句具体事实或反常现象起势，迅速建立当天核心问题。

### 2. What Moved
只讲真正影响当天定价的市场变化。指数涨跌不是必报项。

### 3. Why It Mattered
解释当天最重要的机制链条，例如：

```
Strong PMI
→ More tightening priced
→ 10Y back above 5%
→ Higher discount rate
→ Growth / AI multiple pressure
```

### 4. From Macro to Tape
把宏观判断映射到实际盘面：breadth、板块轮动、相对强弱、市场是否验证宏观假设。

### 5. Trading Map
不列完整指标表，只保留：
- 哪些方向值得优先观察；
- 为什么；
- 等什么确认；
- 什么情况说明原判断失效。

### 6. Previous Call / Model Update
只保留真正值得复盘的一到两个点。判断错了说明误差来源；判断对了也说明真正起作用的因子。

### 7. Tomorrow Watch
结束前留下 2–3 个次日观察变量，并说明这些变量分别会验证或推翻什么判断。

## 口播语言规则

### 必须做到

- 像成熟财经记者或研究员在解释市场，而不是念报告；
- 句子长短自然，不刻意一行一句；
- 先讲现象，再补数字；
- 一个数字如果不改变理解，就删掉；
- 专业术语可以保留，但第一次出现时要让非专业听众也能跟上；
- 不牺牲限定条件、反证和数据边界；
- 观点必须能够追溯到当天正式研究报告。

### 默认弱化或删除的表达

除非确有必要，避免：
- “今天最重要的一句话是”；
- “如果只记住一句话”；
- “接下来我们来看”；
- “从宏观切到……”；
- “首先 / 其次 / 最后”反复出现；
- “这意味着”连续使用；
- “真正值得注意的是”反复使用；
- “我觉得”“说白了”“挺有意思”“市场还能忍”等高频个人评论；
- “这并不意味着……而是……”连续套用；
- 机械总结每一个小节；
- 为了显得完整而朗读表格、参考文献、方法说明。

### 数字规则

音频里一般只保留三类数字：

1. 改变政策或市场判断的数字；
2. 关键阈值；
3. 后续验证条件需要的价格或指标。

其余数字留在文字版研究报告里。

## Research Integrity

- 播客脚本的事实和方向判断必须能追溯到当天正式研究报告；
- 不因“节目效果”夸大确定性；
- 不把 Prediction Ledger 的方向判断包装成投资建议；
- 不能在音频版补入报告信息边界之外、当时尚未公开的数据；
- 若口播为了流畅省略限定条件，必须确保没有改变原结论；
- 完整来源和数据口径保留在对应 Macro Diary / Market Radar 中，不在音频中逐条朗读。
