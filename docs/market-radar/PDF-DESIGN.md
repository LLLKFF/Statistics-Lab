# Market Radar PDF 设计规范

与 Statistics Lab `Global Macro Research Note #001` 的已定稿 PDF 共用一套视觉语言：A4 竖版、白底、深海军蓝主色、浅蓝灰信息框、克制的细分隔线；封面及收尾页沿用雪山品牌视觉、Statistics Lab 标志与「独立思考 / 数据驱动 / 长期视角」。中文标题使用 Noto Sans CJK SC Bold，长正文优先 Noto Serif CJK SC，英文字体保持简洁无衬线；封面与页眉标明 `ASSET OBSERVATION / MARKET RADAR`，不误写成宏观报告。Radar 独立编号，观察日期与宏观日报使用同一个美东交易日。

## 建议页序（约 6–8 页，按当日内容收放）

1. **封面**：左上 Statistics Lab 品牌、右上系列名和期号/日期；左侧中文主标题、英文副标题、「市场判断 Market View」和 4–6 项「市场快照 Market Snapshot」；右侧雪山。快照可选 SPY、QQQ、IWM、主线 ETF、VIX 与当日真正重要的宏观变量，每项写值、单位、日期或观察时点。
2. **交易结论**：顶部一句话说明当期市场、先看什么以及何时观望。按条件清晰度列多空候选，每方向最多两只，可少于四只；每只用固定卡片展示方向、顺序、标的、选取证据、触发条件、放弃条件、历史收盘/关键位/ATR14。页眉显著标明「截至 YYYY-MM-DD 收盘，触发条件尚待核对」。这一页优先服务于快速决策，其余指标下沉到后文。
3. **宏观如何映射到市场**：先引用同一交易日 `Global Macro Research Diary` 的核心结论与链接，再用简短三列把「宏观变量 → 可观察传导 → 指数/板块实际表现」串起来；若盘面未验证宏观判断，明确写出分歧，不把同日相关性写成因果证明。
4. **市场结构与板块**：指数 EMA 趋势、市场广度、板块相对 SPY 强弱，选 2–3 张真正增加信息的图或表。图上标明样本数、期间、来源。必要时可加市场内部分化，而不机械填满图表。
5. **核心标的与关键价位**：只展开优先候选和必要备选。每只写最新价、EMA20/100、近期高低点、ATR14/收盘占比、OBV/CMF 与成交确认；说明「价格现在离关键位多远」，不把 `±1 ATR` 画成天然支撑、目标或固定止损。若没有历史连续数据，使用数值表，不伪造走势曲线。
6. **情景与复盘**：写清「若指数和主线共振 → 做什么」「若弱势反抽失败 → 做什么」「若两边都没有条件 → 观望」；回看上期候选是否触发/失效/仍等待，记录判断哪里需要调整。结论只写研究场景，不代替个体账户仓位与风险预算。
7. **结论与展望**：沿用宏观日报的收尾页：3–4 条 Key Takeaways、精简的 Primary References、正式 Disclaimer、雪山收尾视觉和 Statistics Lab 品牌。完整口径/来源可在此前页面或附页展开，保持链接可核查。

## 制作与发布约束

- 数据先于版式：只用完整的同一交易日收盘数据；宏观日报发布后再生成 Radar PDF。价格、均线、ATR 和成交口径必须和 Markdown 报告一致；图表与交易结论不得出现互相矛盾的日期和数值。
- 版心建议左右约 16–18 mm；正文不小于约 9 pt，图注可略小但要可读。避免把四只标的与全部指标塞进一张窄表，也避免大段孤立分页。
- OBV/CMF 标作价量压力代理，不能写成实测净资金流。所有候选必须写触发和放弃条件；如果数据不全或没有合格机会，在结论页明确说观望。
- 正式文件名使用 `Statistics-Lab_Market-Radar_NNN_YYYY-MM-DD.pdf`。`NNN` 是 Radar 自己的三位编号，与宏观日报的期数各自独立；PDF、封面和 GitHub 正文必须一致。正式 PDF 保存为订阅邮件可读取的持久文件；GitHub 同步当期 Markdown 与阅读索引。若已有经验证的二进制上传流程，可另存 `reports/market-radar/`，不把该上传当作邮件的唯一附件来源。样张文件名不占正式期号。
- 导出后逐页检查中文字体、图表标注、数据日期、跨页表格、页脚、References 和 Disclaimer；用渲染图检查重叠和断页，再发布。

目前的两页版式样张使用 **2026-09-22 历史数据**展示封面与交易结论页，只作视觉说明；以后每一期要按当期数据重新写结论。

## 与宏观日报共同发送

宏观任务先写入同日 GitHub Diary 并制作、保存正式宏观 PDF；Radar 在同日 Diary 存在后撰写、核对当期 Markdown，再制作并保存正式 Radar PDF。订阅邮件由独立任务在两份 PDF 都存在、日期和期号一致且可读取时一次发送，正文用简短两段说明宏观核心判断与 Radar 的多空观察方向、触发/观望条件，随信附两份正式 PDF，并链接 GitHub 两篇正文。发送前查重同日已发送记录；订阅地址只保存在受限的发送任务中，不写入公开仓库，发送使用逐一邮件或 BCC 保护隐私。若文件缺失或关键行情尚未核实，则延后推送并说明缺口，不把前一天文件充当当日报告。
